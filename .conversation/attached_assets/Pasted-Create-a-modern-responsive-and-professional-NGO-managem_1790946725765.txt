Create a modern, responsive and professional NGO management website frontend for **People for Passion**, a registered non-profit organization focused on creating positive social change through community service.

The website should have two major areas:

1. Public-facing NGO website
2. Admin management dashboard

The frontend should be designed as a real production-quality NGO platform rather than a generic template.

## Organization Name

## About the NGO

People for Passion is a non-profit, registered organization consisting of passionate people working towards the community to bring about positive change in society.

The organization was founded in 2019 by **Harshitha Srinivas**. The organization works with passionate volunteers and community members to support marginalized and underserved sections of society.

# DESIGN DIRECTION

Create a warm, trustworthy and modern NGO visual identity.

The website should feel:

* Human
* Compassionate
* Trustworthy
* Community-oriented
* Professional
* Accessible
* Hopeful
* Modern

Avoid making it look like a corporate SaaS dashboard on the public website.

Use a clean visual hierarchy with:

* Large meaningful imagery
* Rounded cards
* Soft shadows
* Generous whitespace
* Accessible typography
* Subtle animations
* Clear calls-to-action

Suggested visual palette:

* Warm maroon / deep red as the primary color
* Soft cream/off-white background
* Dark charcoal text
* Muted green accents for community/environment sections
* White cards
* Subtle neutral borders

Do not overuse gradients.

Use authentic-looking NGO/community imagery where image assets are available. Avoid generic corporate stock imagery.

# 9. ROLE-BASED ACCESS CONTROL UI

Design the frontend to support different admin roles.

Roles:

### Super Admin

Can:

* Manage users
* Manage beneficiaries
* Manage programs
* Manage events
* View reports
* Modify settings

### Admin

Can:

* Manage beneficiaries
* Manage programs
* Manage events
* View reports

### Volunteer / Staff

Can:

* View assigned beneficiaries
* Add beneficiary records
* Update beneficiary information
* View programs

The UI should conditionally display navigation items according to the user's role.

Create a reusable permission system such as:

`hasPermission(user, permission)`

Permissions could include:

* `beneficiary.view`
* `beneficiary.create`
* `beneficiary.edit`
* `beneficiary.delete`
* `program.view`
* `program.create`
* `program.edit`
* `event.view`
* `event.create`
* `event.edit`
* `user.manage`
* `reports.view`
* `settings.manage`

# 19. OVERALL EXPERIENCE

The final website should feel like a real NGO platform that combines:

PUBLIC WEBSITE
→ Story
→ Mission
→ Programs
→ Events
→ Community impact
→ Volunteer CTA
→ Contact

WITH

ADMIN PLATFORM
→ Dashboard
→ Beneficiary management
→ Search & filtering
→ Program management
→ Event management
→ Role-based access
→ Reports

The public website should prioritize storytelling and trust.

The admin dashboard should prioritize efficiency, clarity and data management.

Build the frontend with clean reusable components and keep the architecture ready for future REST API/backend integration.

Do not hard-code the application logic into individual pages. Keep mock data in separate data/service files so that it can easily be replaced by backend APIs later.

Make the website visually polished enough for an NGO project presentation/demo and structurally scalable enough to become a real production application.
